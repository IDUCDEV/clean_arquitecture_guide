Fundamentos: los 3 árboles y la regla de oro

widget · element · render

En Flutter todo es un widget: una descripción inmutable de la UI. El modelo es declarativo — describes cómo debe verse la UI para un estado y Flutter la lleva ahí.

Widgetconfiguración, barato de crear/descartar Elementinstancia mutable que Flutter reutiliza RenderObjectlayout + paint en pantalla

Stateless vs Stateful

StatelessWidgetStatefulWidget
Estado mutableNoSí (vive en la clase State)
Reconstruye porNuevas propiedades / contextoPropiedades + setState()
Usa cuandoSolo depende de props y contextoNecesita estado efímero interno

Regla de oro: ¿el widget cambia con el tiempo? No → StatelessWidget · Solo por datos externos → StatelessWidget + Stream/Future · Estado efímero interno → StatefulWidget.

Claves rápidas

  • BuildContext = el "lugar" del widget en el árbol (acceso a Theme.of, Navigator, MediaQuery.sizeOf).
  • const en todo widget que no cambie → Flutter se salta su reconstrucción.
  • Keys: ValueKey (identificador), ObjectKey (objeto), UniqueKey (forzar re-creación), GlobalKey (acceder desde fuera).

Atomización (atomic design)

Átomos (Text, Icon, Chip, Botones) → Moléculas (Card, ListTile, AppBar, NavigationBar) → Organismos (Formulario, Lista, Scaffold) → Plantillas → Páginas.

Crea widgets atómicos propios (AppText, UserAvatar) para consistencia; hazlos const y sin estado cuando sea posible.

Layout y Navegación

Row · Stack · Scaffold · GoRouter

Row / Column / Stack

Row = eje horizontal · Column = eje vertical. mainAxisAlignment sobre el eje principal, crossAxisAlignment sobre el secundario. Expanded reparte espacio proporcional (flex), Flexible permite encoger. Stack + Positioned superponen capas.

Scaffold (M3)

Barra inferior: NavigationBar + NavigationDestination (M3). Drawer: NavigationDrawer. BottomNavigationBar y Drawer son legacy M2.

Navegación

APIUso
Navigator 1.0Navigator.push/pop imperativo, rutas por clase
GoRouter (recomendada)Rutas declarativas con GoRoute, params, redirects; context.go/push/pop; pubspec: go_router ^17.5.0
PopScopeIntercepta el botón atrás (reemplaza WillPopScope)

Responsive: usa MediaQuery.sizeOf/widthOf/heightOf (no MediaQuery.of().size) para decidir por pantalla, y LayoutBuilder para decidir por el espacio del padre.

Interacción y Formularios

validación y selección

Formularios

Form(key: GlobalKey<FormState>) + TextFormField(validator:). validate() corre todos los validators; save() dispara onSaved. Controladores (TextEditingController) siempre en dispose().

Selección y controles M3

ControlNota clave
DropdownButtonFormFieldUsa initialValue (no value, deprecado 3.35)

RadioDentro de RadioGroup; groupValue/onChanged deprecados en Radio

Patrón de formulario sin librerías

Form(key: _formKey) → campos TextFormField con validator
Botón: FilledButton habilitado según estado
Estado local: ValueNotifier<bool>(_enviando) + ValueListenableBuilder

Adelanto módulo 16: el mismo árbol de widgets se mantiene con BlocProvider + BlocListener + BlocBuilder. La estructura del formulario no cambia, solo quién gestiona el estado.

Datos, Estado y Ciclo de Vida

flujo unidireccional

Los datos viajan hacia abajo; los callbacks hacia arriba (lifting state up).

Ciclo de vida StatefulWidget

constructor → initState → didChangeDependencies → build
(padre cambia) didUpdateWidget → build
(desmonta) dispose
// setState() programa una reconstrucción del subárbol

Widgets reactivos

WidgetEscuchaUso

mounted vs context.mounted: mounted (en el State) protege setState tras un await; context.mounted (en el BuildContext) protege operaciones con context (navegación, SnackBar, context.read).

6

Animaciones

implícitas vs explícitas

Implícitas (cambia el target, Flutter interpola)

AnimatedContainer, AnimatedOpacity, AnimatedPadding, AnimatedSwitcher, AnimatedPositioned, AnimatedAlign, AnimatedSlide/Scale/Rotation, TweenAnimationBuilder. Personalizables con AnimationStyle.

Explícitas (control fino)

AnimationController (+ SingleTickerProviderStateMixin) → Tween → CurvedAnimation → AnimatedBuilder. Con AnimationStatusListener para repetir/invertir y Interval para animaciones escalonadas.

Extras

  • Hero: transición compartida entre pantallas con el mismo tag.
  • CustomPainter: dibujo vectorial (paint + shouldRepaint).
  • Lottie/Rive: animaciones JSON de After Effects.

Reglas: implícitas primero · ~300ms en interacciones táctiles · no animes opacity+size juntos · usa FadeTransition en loops (no Opacity).

Estrategias de Composición

composición > herencia
  • No heredes widgets: compón con parámetros (AccionBoton envuelve un FilledButton).
  • Slots: expón child (contenido fijo) o builder (contenido que depende del contexto).
  • Widgets privados anidados (_Body, _InfoSection) → sub-árboles const que se reconstruyen independientemente.
  • Una responsabilidad por widget (Page / View / Card / Tile / Form / Dialog…).
  • Builder pattern: crear un contexto hijo para SnackBars y similares.

InheritedWidget: mecanismo interno de Theme, MediaQuery y BlocProvider. Entiende cómo funciona, no lo reimplementes.

8

Patrones de Renderización

loading · error · empty · data

Renderizado condicional

Ternario → collection-if / collection-for → Visibility (con maintainSize/maintainState).

Estados con clases selladas (Dart 3)

sealed class AsyncState<T>
  ├─ AsyncLoading<T>
  ├─ AsyncError<T> (message)
  └─ AsyncData<T> (data)

UI: switch (estado) → loading spinner / error + reintentar / empty / builder(data)

Scroll y vistas

  • Slivers: AppBar colapsable + listas + grids en CustomScrollView.
  • NestedScrollView: header que colapsa con Tabs en el body.
  • IndexedStack: mantiene vistas montadas (no pierde estado). PageView: swipe.
  • Shimmer/Skeleton: placeholders animados mientras carga.
  • Overlay/Popup: bottom sheets, tooltips, PopupMenuButton.
  • Callback pattern: el hijo notifica al padre (inversión de control).
