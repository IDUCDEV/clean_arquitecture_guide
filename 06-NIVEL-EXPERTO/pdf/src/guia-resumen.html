PARTE I — Programación Funcional

01. fpdart: Result Pattern con Either y Option

Objetivo: Eliminar exceptions del dominio usando tipos funcionales.

Dart tradicional → fpdart
try-catch / null → Either<L, R> / Option<A>
Excepciones ocultas → Errores explícitos en tipo
Conceptos Clave
  • Either<L, R>: izquierda (error) | derecha (éxito)
  • Option<A>: Some(value) | None — reemplaza null
  • TaskEither<L, A>: Either diferido (async)
  • flatMap: encadenar operaciones que retornan Either
  • fold: convertir Either a valor final en Cubit
Puntos Clave:
  • Repository retorna Either<Failure, T>
  • UseCase propagar con flatMap
  • Cubit consumir con fold: left → error state, right → success state
  • TaskEither para operaciones async antes de ejecutar
Tip: TaskEither.sequence() ejecuta múltiples tareas en paralelo y retorna Either<L, List<R>>.

06. json_serializable y Freezed

Objetivo: Data classes inmutables con serialización automática.

Clase anotada → build_runner → .g.dart + .freezed.dart
Combinación Ideal
  • @freezed: inmutabilidad, copyWith, ==, hashCode
  • @JsonSerializable(): fromJson / toJson automáticos
  • Freezed genera la estructura, json_serializable la serialización
Regla: Si un modelo tiene 3+ campos, usa freezed + json_serializable. El tiempo ahorrado justifica la configuración inicial.

07. Retrofit: Clientes HTTP Generados

Objetivo: APIs tipadas con interceptors y generación automática.

Pilares de Retrofit
  • @RestApi(): define la interfaz HTTP
  • @GET/@POST/@PUT/@DELETE: endpoints anotados
  • Dio: motor HTTP subyacente
  • Interceptors: auth, logging, retry, errores
Integración:
  • Retrofit + json_serializable: modelos generados automáticamente
  • Retrofit + injectable: cliente registrado en DI
  • Retrofit + freezed: respuestas inmutables con patrón Either

PARTE IV — Dart 3 y Debugging

09. Dart 3 Pattern Matching Nativo

Objetivo: Manejo exhaustivo de tipos sin dependencias externas.

Sintaxis Dart 3
switch (valor) {
  int n when n > 0  => 'Positivo',
  0                 => 'Cero',
  int n             => 'Negativo',
  String s          => 'Texto: $s',
  _                 => 'Otro tipo',
}
Características:
  • Sealed classes: jerarquías de tipos con cases exhaustivos
  • Guards: when para condiciones adicionales
  • Destructuring: extraer campos de objetos y listas
  • Alternatives: || para combinar patrones
  • Sin dependencias externas — compilador fuerza exhaustividad
vs fpdart: Dart 3 pattern matching es ideal para estados sealed. fpdart (Either/Option) es mejor para flujos funcionales encadenados.
